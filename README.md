# agent-runtime

围绕 AI 应用常见执行问题构建的 Python Agent 运行时参考实现，覆盖工具调用、结构化输出校验、执行记录、异步回调与流式响应。

本项目基于本人开发的万小课 AI 服务进行独立重建与验证：从 HTTP 模型调用开始，逐步抽离公共执行机制，再通过 LangChain 适配层验证模块边界。它是工程验证与教学用途的实现，不是线上服务源码的完整公开版本。

## 解决的问题

- **工具调用如何结束：** 管理模型与工具之间的消息循环，区分正常完成、步数耗尽和调用异常。
- **生成结果如何验证：** 将结构校验与业务校验分开，收集问题并反馈给模型，在有限次数内重新生成。
- **执行失败如何留痕：** 为每次运行及步骤记录状态、token、成本和耗时，统一处理正常与异常收尾。
- **业务服务如何接入：** 通过 FastAPI 接收任务，异步执行并回调结果；问答场景通过 SSE 返回内容。
- **依赖异常如何处理：** 通过请求超时、熔断及超时运行记录回收，处理模型服务故障和未完成任务。

## 实现范围

| 模块 | 主要能力 |
| --- | --- |
| 模型调用 | HTTP 客户端与 LangChain 适配层，统一消息、工具调用及 usage 表示 |
| Agent 循环 | 工具注册与执行、工具结果回传、步数上限及异常处理 |
| 结构化输出 | 通过工具调用协议请求结构化结果，使用 Pydantic 校验，并调用业务检查函数 |
| 执行记录 | 使用 SQLite 保存 run / step，记录状态、token、成本、耗时及错误 |
| 生命周期 | 使用 `tracked_run` 统一建立记录和执行收尾，保留失败前已累计的用量 |
| 异步服务 | FastAPI 任务入口、内部接口认证、后台执行与结果回调 |
| 流式输出 | SSE 的 `meta`、`delta`、`done`、`error` 事件，以及客户端断开处理 |
| 故障处理 | 请求超时、closed / open / half-open 熔断、超时运行记录回收 |

## 分层设计

```text
业务入口 / 示例 Agent
    │  提供工具、输出 Schema 与业务校验
    ▼
运行时
    ├── Agent 循环与结构化输出重试
    ├── run / step 记录与统一收尾
    └── 超时与熔断
    ▼
模型适配层
    ├── HTTP 客户端
    └── LangChain 适配器

FastAPI 接入层 → 后台任务 / SSE → 业务服务或客户端
```

运行时通过统一的数据结构访问模型客户端。LangChain 适配层负责消息与响应转换，保留工具参数原文及无效工具调用信息，使上层能够继续执行校验和错误反馈。

本项目采用自定义执行循环；LangChain 在这里主要承担模型客户端适配，不代表它只能用于这一层。是否引入 LangGraph 等编排方式，取决于业务的状态和分支需求。

## 关键工程案例

### 分开记录任务失败与回调失败

Agent 执行成功后，结果回调仍可能因网络或地址问题失败。如果将两者放在同一异常处理块中，会把已经成功的任务误记为失败。

实现中分别处理任务执行和结果回调，保留各自状态与日志。调用方仍需处理结果未送达的情况，例如超时检查或后续补偿。

### 失败时保留已发生的用量

token 与步骤信息随运行对象累计，成功和失败路径共用同一份状态。统一收尾时保存已有记录，避免任务失败后将已发生的模型调用用量清零。

### 将校验问题反馈给模型

运行时负责格式校验，业务侧负责内容约束。校验失败时，将具体问题送回模型，并限制重试次数。实验中曾出现校验阈值与错误提示不一致，导致模型反复生成不合格结果，因此约束条件和提示应使用一致的参数来源。

### 处理流式中断与残留状态

客户端断开时，记录已生成内容并将运行标为中止；对于进程中断等未正常收尾的情况，定期将超时的运行记录标为失败。若供应商仅在最后一个流式事件返回 usage，中途断开可能无法取得完整 token 统计。

### 用可控时钟验证熔断行为

为熔断器注入时钟，在测试中推进时间，验证打开、冷却、半开探测与恢复，无需实际等待；同时检查熔断期间是否阻止了底层请求。

## 验证与实现边界

开发过程中进行了工具协议异常、结构化输出重试、错误凭据、回调失败、流式中断及熔断状态转换等验证。这些是局部测试和故障实验，不代表生产负载下的完整可靠性验证。

- **存储：** 当前参考实现使用 SQLite，未完整复现线上服务的 PostgreSQL 数据模型及租户、用户、会话、提示词版本等记录维度。
- **后台任务：** 使用 FastAPI `BackgroundTasks`，不提供持久化任务队列保证；进程退出可能导致任务中断。
- **任务回收：** 回收是对超时运行记录进行状态修正，不等同于自动恢复或重新执行任务。
- **租户上下文：** 示例将租户信息放入执行上下文，避免由模型填写工具参数；这不等同于完整的数据隔离与权限体系，业务服务仍需执行授权检查。
- **结构化输出：** 工具调用协议不能保证生成内容始终正确，仍需结构校验、业务校验及失败处理。
- **回调与外部操作：** 不应据此假设已有完整的回调可靠送达、分布式幂等或故障补偿能力。
- **业务范围：** 完整的知识库、业务 Agent、评测平台及多租户平台能力不应视为本仓库已全部提供。

## 实现过程

项目按以下顺序逐步构建，便于理解各层职责与演进原因：

1. 模型 HTTP 接口与响应解析
2. 工具调用协议与消息回传
3. Agent 循环与退出条件
4. run / step 执行记录
5. 上下文管理器与统一收尾
6. 结构化输出与校验重试
7. FastAPI 后台任务及结果回调
8. SSE 事件协议与流式中断
9. 超时、熔断与运行记录回收
10. LangChain 适配层与实现对照
